01 / System logic

Design principles

The interface should feel like one connected system—not a collection of individually styled pages.

01 · Foundation

Tokens before components

Color, type, spacing, radius, and motion live in named CSS custom properties. Components consume tokens instead of repeating arbitrary values.

02 · Composition

Primitives compose upward

Fields, buttons, badges, panels, and tables form larger patterns. Page layouts arrange patterns without redefining their visual behavior.

03 · State clarity

State is explicit

Default, hover, focus, selected, disabled, success, warning, and error states should be visible and predictable.

04 · KISS

Use the smallest useful layer

Semantic HTML first; CSS for presentation; vanilla JavaScript for behavior. No framework is required for the design system.

05 / Components

Buttons & actions

Use visual weight to communicate action priority. Keep one dominant action per decision area.

Rules

  • Use gold fill for the primary action.
  • Use outline or quiet styles for secondary actions.
  • Destructive actions use semantic danger styling and should be unambiguous.
  • Always provide keyboard focus and a disabled state when applicable.

09 / Components

Navigation patterns

Navigation tells people where they are and what is available without competing with the content.

Overview panel — show the most relevant summary and primary next action.
Activity panel — show a chronological, scannable record of meaningful events.
Settings panel — group configuration by task and preserve clear labels.

Desktop side navigation can collapse into a horizontally scrollable section bar on smaller screens. Tabs are for switching peer views, not replacing links to separate destinations.

Icon style

Prefer simple outline SVGs with rounded joins, consistent stroke weight, and currentColor. Gold marks primary emphasis; mint is suitable for positive or active states. Do not mix filled, outlined, and emoji icons within the same component set.

12 / Loading states

Skeleton system

Use skeletons when the layout is known but content has not arrived. Keep geometry close to the loaded component to avoid layout shift.

For content cards with media, title, summary, and action.

  • Media100–160px
  • Title bar17px
  • Text bar10px / 6px gap
  • Shimmer1.65s ease-in-out

List / profile skeleton

For lists, people, search results, or compact records.

  • Avatar42px / 34px
  • Row gap12px
  • Base surface--skeleton-base
  • Highlight--skeleton-highlight

Skeleton implementation

.skeleton { position: relative; overflow: hidden; background: var(--skeleton-base); } .skeleton::after { content: ""; position: absolute; inset: 0; transform: translateX(-100%); background: linear-gradient(100deg, transparent, rgba(205,225,211,.17), transparent); animation: skeleton-shimmer 1.65s ease-in-out infinite; } @keyframes skeleton-shimmer { to { transform: translateX(100%); } }

Implementation note: mark the loading container with aria-busy="true" and provide a screen-reader status such as “Loading items”. Respect prefers-reduced-motion; never use shimmer as a permanent decoration.

15 / Engineering contract

Implementation rules

The design system is a small, dependency-free layer. Keep visual rules declarative and behavior explicit.

Recommended structure

/ayrex-ui style.html # living reference tokens.css # design variables base.css # reset + typography components.css # reusable primitives patterns.css # composed patterns interactions.js # optional behavior

Rules of use

  • Prefer semantic HTML and native controls.
  • Use tokens for all shared visual decisions.
  • Do not add page-specific styles to shared components.
  • Keep state and behavior separate from presentation.
  • Support keyboard focus, reduced motion, and narrow screens.
  • Extend the system only when a real repeated need appears.

Token contract

/* Component API: stable semantic names */ .button-primary { background: var(--color-accent); } .button-secondary { border-color: var(--color-accent); } .text-muted { color: var(--color-muted); } .surface-panel { background: var(--color-surface); } /* Page-specific composition belongs outside components */ .initiative-grid { display: grid; gap: var(--space-4); }
